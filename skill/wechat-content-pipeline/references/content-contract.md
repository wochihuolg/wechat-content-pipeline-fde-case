# Content contract

## Inputs

Accept one or more PDF, Markdown, or UTF-8 text files. Treat them as read-only
knowledge sources.

Collect the account positioning, target audience, desired topic count, output
directory, and local env-file path before execution.

## Topic plan

Write `topic_plan.json` and `选题矩阵.md`. Every topic must contain:

- a stable numeric index and ASCII slug;
- a high-click working title and a compact title no longer than 20 characters;
- one concrete pain point and one promise;
- one reusable deliverable;
- one or more valid source references;
- a next-post hook.

Reject duplicate titles, duplicate slugs, invalid references, unsupported
claims, and ideas that cannot support six distinct images.

## Article directory

Name directories `NN_ascii_slug`. Write:

- `来源卡.md`: exact source locations, synthesis, fact checks, and copyright
  boundaries;
- `公众号终稿_图片标注版.md`: opening scene, exactly three numbered sections,
  one reusable action card, action ending, and hook;
- `贴图指令.md`: public title, description, and exactly six image sections.

Use short spoken Chinese paragraphs. Avoid empty management jargon, fabricated
data, fake tests, and generic tutorial openings.

## Six-image contract

Use exactly one cover and five content images. Each image instruction must
include:

- position;
- layout;
- exact display text;
- supporting visual elements;
- color direction;
- forbidden elements.

Make the cover legible as a phone thumbnail. Preserve brand and tool names when
they are central to the topic. Do not use unrelated logos or imply an official
partnership.

## Copyright and evidence

- Use source material as knowledge clues, not copy.
- Do not remove watermarks from source images; create new assets.
- Do not reproduce original screenshots, page layouts, or long passages.
- Record time-sensitive facts for manual verification before public release.
- Use real execution evidence for any statement that implies testing.
