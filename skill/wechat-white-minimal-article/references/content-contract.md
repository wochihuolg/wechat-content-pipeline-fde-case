# 内容合同

## 输入

接受 PDF、Markdown 或 UTF-8 文本。将来源视为只读，记录账号定位、目标读者、篇数、输出目录和本地环境文件。

## 批次文件

- `topic_plan.json`
- `选题矩阵.md`
- `公众号贴图短标题.json`：为兼容旧流程保留文件名，值必须是完整栏目标题。
- `image_generation_manifest.json`
- `公众号贴图草稿清单.json`
- `公众号永久素材缓存.json`
- `公众号贴图草稿结果.json`

## 文章目录

目录名使用 `NN_ascii_slug`，每篇必须包含：

- `来源卡.md`：来源位置、事实综合、时效性检查和版权边界。
- `公众号终稿_图片标注版.md`：完整标题、短段落正文、适用与不适用边界、总结。
- `贴图指令.md`：完整公众号标题、摘要和六张图的确定性指令。

`贴图指令.md` 必须包含：

```markdown
文章：每天介绍一个 AI 产品：{产品名}

## 公众号标题
每天介绍一个 AI 产品：{产品名}

## 公众号摘要
60-100 字摘要
```

后续必须有且仅有 `### 图片1` 到 `### 图片6`。每张图包含定位、布局描述、文字内容、视觉元素、配色建议和避免元素。

## 标题一致性

以下值必须完全一致：

1. `贴图指令.md` 的“公众号标题”；
2. `topic_plan.json` 的 `title` 与 `compact_title`；兼容旧项目的 `working_title`；
3. `公众号贴图短标题.json` 对应值；
4. 草稿清单的 `original_title` 与 `draft_title`；
5. 草稿结果的 `draft_title`；
6. 微信 `draft/get` 返回标题。

标题最长 32 字。任何缩写、空格变化、产品大小写变化都应在保存前阻断。

## 完成条件

- 选题数等于文章目录数；
- 每篇三个 Markdown 文件齐全；
- 每篇六个图片指令和六张生成贴图；
- 草稿结果全部 `saved`；
- 草稿 ID 均存在且唯一；
- 标题一致性检查通过；
- `failed=0`、`needs_update=0`、`published=0`。
